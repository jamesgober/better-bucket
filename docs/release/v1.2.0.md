# better-bucket v1.2.0

A fix release with two additive methods. No call site changes.

## Fixed

**Refunds on very fast buckets.** Above about 4.3 x 10^9 tokens per second the
bucket counts in units of several tokens. `refund` rounded each refund up to a
whole unit, so refunding a grant in small pieces credited more tokens than it
returned. Refunds now round down. A refund never credits more than it returns,
and a refund of less than one unit credits nothing. Every rate up to about
4.3 x 10^9 tokens per second, which covers every `u32` amount per second, was
exact before and is unchanged.

**`cargo test` with clock-lib 1.2.** clock-lib 1.2 makes `Monotonic` larger in
debug builds, so `Bucket<SystemClock>` takes two cache lines there. The layout
test now checks the one-line size in release builds, where it holds, and the
README says "in release builds". `BucketCore` is one line in every build.

## Changed

**`metrics` counters on their own cache line.** The counters used to share the
line that holds the state, so each denial wrote to the line a granting CAS
needs. They now sit on a second line. In an 8-thread denial flood on the test
host, a denial with `metrics` costs about 65 to 90 ns, down from 130 to 160 ns,
against about 5 ns without `metrics`. `BucketCore` is 128 bytes with `metrics`
as before. `Bucket<SystemClock>` is 192 bytes with `metrics` in release builds
(it was 128).

The README now explains what `metrics` costs. Cargo unifies features, so one
crate that enables `better-bucket/metrics` turns it on for every user of the
crate in that build. Enable it in the final application, not in a library.

## Added

- **`charge(n)`**, **`charge_at(n, now)`**: record usage that happened outside
  the bucket as debt, with no capacity check, in one CAS loop whatever `n` is.
  The debt is not capped, so bound a number you do not trust first.
- **`postpone_at(by, at)`**: move the schedule `by` later, as if the clock had
  stood still from `at`. Reservations made before a pause then keep their
  spacing when the pause ends instead of all coming due at once. It never adds
  tokens.

Both are on `Bucket` and `BucketCore`; they are not on the `TokenBucket` trait.

## Compatibility

MSRV 1.85, edition 2024, as before. `cargo semver-checks` reports no breaking
change against 1.1.0.
